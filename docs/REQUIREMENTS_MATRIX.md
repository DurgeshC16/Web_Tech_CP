| Trust score + verification report (Phase 2) | Rule-based 0–100 score from the EXISTING checks only — `TrustScoreService` replays `VerificationService` order read-only (exists 20 / hash 30 / signature 30 / not-expired 10 / not-revoked 10); failed critical check (exists/hash/signature) caps score at 40; score can never contradict the verdict (exact-equality tests per verdict). Panel with semicircular SVG gauge + per-check checklist + disclaimer ("…does not verify the real-world achievement") on `verify.php` result view; "Download verification report" button → `public/report.php` (dompdf via Composer `vendor/`, committed with composer.json); PDF shows only public facts (verdict, score/checks, cert fields incl. SHA-256, algorithm note, QR linking back to live verify page) and never tokens/keys/file paths; domestic rate limit 5 downloads/10 min/IP via `verification_logs` marker rows + audit logging; missing-dompdf graceful 503 fallback page with the same facts | Yes |
| Transparency + public status API (Phase 3) | `public/api_status.php` (`?certificate_id=`/`?id=`) → JSON `{api, generated_at, verdict, detail, certificate{public fields}, trust_score{score, checks, disclaimer}, superseded_by?}`; verdict ALWAYS from `VerificationService` (via testable `StatusApiService`; verdicts/NOT_FOUND are never decided by the API layer); NO tokens/keys/signatures/file paths in output; format-guarded 404 `NOT_FOUND` (never 500 for bad input); rate-limit + audit logging via `verification_logs` markers, off-switch `CV_API_ENABLED` (config `API_ENABLED`, default ON); transparency strip on `institutions`' `audit_logs.php` — outcome-mix counts + top non-VALID reasons from `v.detail` | Yes |

Not fully implemented / noted:
- External-source records are shown as *unverified information* by design (CertiVault
  cannot verify external signatures); the feature is documented in README under
  "External verification sources" and ships disabled.
- A real-device spot check (phone + desktop) is still worthwhile for feel
  issues automation cannot judge (QR camera scan, toast timing); layout
  itself is verified headlessly (see docs/TEST_PLAN.md #24).
